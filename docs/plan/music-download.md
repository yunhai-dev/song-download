# 双平台音乐下载设计

## 背景与目标

在空 Rust 工程中实现 GPUI 桌面端。用户能选择 QQ 音乐或网易云音乐，扫码查看本人歌单，再下载账号可访问的整首音频、专辑封面和平台提供的逐字歌词。不开会员解锁，不用试听冒充整首，不推算逐字时间戳。

## 概要设计

GPUI 按平台保存会话和歌单状态。网络与磁盘操作不占用 UI 线程。应用启动本地 Node 适配器，复用 Folia Major 同版本的两个 API 包；两家上游的字段和错误由各自 Rust 模块处理。适配器只监听随机回环端口并校验随机令牌，不接受外部连接。登录凭据经系统钥匙串保存，详见[登录状态持久化](login-persistence.md)。

## 实施步骤

### 1. 工程与适配器
- **文件**：`Cargo.toml`、`package.json`、`bridge/`、`src/music.rs`。
- **逻辑**：锁定依赖，管理子进程与有超时的本地 HTTP 客户端。
- **验证**：编译 Rust；验证桥接入口及缺少适配器时的提示。

### 2. QQ 音乐
- **文件**：`src/music/qq.rs`。
- **逻辑**：处理扫码状态、本人及收藏歌单、可用整首链接、封面和 QRC。歌词解密使用现有 Rust 库。
- **验证**：按上游包的实际路由及响应核对，覆盖扫码已确认和无可用整首的响应。

### 3. 网易云音乐
- **文件**：`src/music/netease.rs`。
- **逻辑**：扫码确认后读取账号；分页获取歌单及曲目；拒绝试听链接，导出 YRC 或上游提供的 LRC。
- **验证**：核对分页、空逐字歌词和试听标识。

### 4. 桌面交互与文件导出
- **文件**：`src/ui.rs`、`src/download.rs`、`src/main.rs`。
- **逻辑**：展示二维码、歌单和曲目；提供单曲下载和目录选择。同名文件不覆盖；可选素材失败时显示具体结果。
- **验证**：检查应用编译和本地交互路径；用本地数据验证写入冲突与失败清理。

## 测试策略

- 正常路径：分别扫码，打开自建与收藏歌单；下载文件并检查音频、封面和逐字时间戳。
- 异常路径：二维码过期、无整首音源、缺少逐字歌词、同名文件、网络或写入失败。
- 离线验证覆盖纯逻辑和协议解析；真实账号扫码和授权下载需要人工联调。

## 风险与处理

第三方 API 可能随平台协议变化而失效。依赖版本锁定；问题局限在相应平台适配层，不迁移用户数据。回退对应集成提交即可恢复前一阶段。歌曲及素材仅供用户在授权范围内保存。
