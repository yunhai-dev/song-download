# 登录状态持久化设计

## 背景与目标

关闭应用会丢失两家平台的登录状态。升级后，扫码成功的会话可以跨重启恢复；退出只移除本机登录，不影响另一平台或手机端。已有内存会话不能迁移，需用新版扫码一次。

## 概要设计

两家平台的 Cookie 分别存入 macOS 登录钥匙串，不写入明文文件。QQ 的 Cookie 是本地适配器的索引，因此还需复用其加密会话仓库；密钥保存在钥匙串，通过子进程的标准输入传给适配器。启动后独立校验两家会话；确认失效才清理，网络失败保留原记录以便重试。

实现位置：钥匙串服务名为 `song-download.login`，歌单账号、Cookie 与 QQ 会话密钥分别使用独立条目。QQ 加密仓库默认位于 `~/Library/Application Support/song-download/qq-sessions.enc`，文件内容由钥匙串中的密钥加密。

## 实施步骤

### 1. 存储与适配器
- **文件**：`src/session.rs`、`src/music.rs`、`bridge/main.cjs`、`Cargo.toml`。
- **逻辑**：用平台专属钥匙串条目存取凭据；通过启动管道配置 QQ 包的加密仓库。无可用钥匙串时保持本次运行可登录，并提示无法记住会话。
- **验证**：使用临时文件和合成凭据验证 QQ 加密存储和恢复，不读取真实账号。

### 2. 启动恢复与退出
- **文件**：`src/ui.rs`、`src/ui/views.rs`、`src/music/qq.rs`、`src/music/netease.rs`。
- **逻辑**：使用账号查询验证 Cookie，成功后加载歌单；明确失效时移除本机记录，临时失败提供重试。显式退出时清除当前平台凭据，QQ 同时撤销本地适配器会话。
- **验证**：测试判定有效、失效和响应异常的差异；用实际账号扫码一次后退出应用再打开，验证恢复。点击退出后再打开，确认不再恢复该平台。

## 测试策略

离线检查会话判定、QQ 加密仓库和原有列表回归。真实账号的持久化、钥匙串授权弹窗与过期行为需在 macOS 手动验证。

已完成的离线验证：QQ/网易云的「有效、明确失效、异常响应」区分有单元测试；适配器用合成 QQ 会话验证了加密落盘、重启读取和错误密钥降级；应用连续启动可正常读取钥匙串。真实账号扫码后退出并重启的恢复流程仍需人工确认。

## 风险与处理

钥匙串不可用时不改为明文存储。网络波动不删除凭据。回退此功能不影响已下载文件；如不再使用持久化功能，先通过新版退出，或在钥匙串访问中删除应用的对应登录条目。
