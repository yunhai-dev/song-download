# 下载管理与列表布局设计

## 背景与目标

当前列表按内容宽度布局，时长、下载按钮和分隔线无法对齐。全局下载开关还会把所有曲目显示为「下载中」。改为 Linear 风格的深色主界面，并让列表与下载管理页共享每首歌曲的真实状态。

## 概要设计

使用平台和曲目 ID 作为任务键（QQ 使用 songmid，网易云使用歌曲 ID）。下载按提交顺序串行执行；浏览、切换平台和继续添加任务不受影响。历史只保存成功记录和产物路径，不保存账号、凭据或待执行任务。音频文件不存在时，不再恢复「已下载」标记。

## 实施步骤

### 1. 下载队列与完成记录
- **文件**：`src/download.rs`、`src/downloads.rs`、`src/ui.rs`。
- **逻辑**：导出返回音频路径和各素材结果；队列按曲目去重，状态为排队、下载中、完成或失败。完成记录原子写入本地应用数据目录；失败可重试，排队项可取消。
- **验证**：覆盖排队顺序、同曲去重、跨平台区分、失败状态及重启恢复。

### 2. Linear 风格与固定列
- **文件**：`src/ui.rs`、`src/ui/views.rs`。
- **逻辑**：深色界面、紫色强调、固定导航；列表显式铺满可用宽度，序号、时长和操作列固定，歌曲信息可伸缩和截断。下载页独立显示所有任务及结果，可定位已保存的文件。
- **验证**：在不同窗口宽度检查长短标题、状态和分隔线；切换平台或列表不改变任务状态。

## 测试策略

模拟连续添加两首歌，检查一首先执行、一首排队、其余不受影响；检查队列取消、失败重试和完成记录恢复。使用不同长度的歌名和专辑名检查列对齐，不需要真实账号参与本地状态验证。

已通过 `cargo test --locked`：队列测试覆盖串行、去重、重试、取消及完成记录恢复；GPUI 测试覆盖 760 和 1060 像素宽度下的列对齐、单曲「下载中」标记及管理页切换。

## 风险与处理

升级前的下载没有可靠的曲目 ID，不能从文件名猜测归属。历史写入失败时保留已保存的文件，并显示错误。回退界面和队列提交不会删除下载文件或历史。
